## 2. What a first-time visitor sees now

- **Landing.** The illustrated studio fills the opening screen. The heading is "Your new gym buddy." The four pillars (set your routine, track every set, watch a quick demo, see your gains) follow straight after. The page has no white cards.
- **Test drive (`/try`).** A two-movement guest workout with approved demos: plan, demo in place, log a set, rest, finish, and a peek at how Progress adds up. Nothing is saved, and the page says so once.
- **Member onboarding.** Five steps:
  1. What are you training for?
  2. How much lifting have you done?
  3. How many days a week can you train?
  4. What do you have to work with? ("Dumbbells" or "Barbell + rack", the same names as Settings and the editor)
  5. Here's your routine.

  The routine is built from the answers by `generateStarterRoutine` and lists demos that open in place. "Prefer a different start?" offers the five-day example or a blank start. After saving, a four-card tour (Today, logging, demos, progress) can be skipped at any point. Skipping or finishing it moves focus to Today's heading. Unverified members can answer and preview but not save.
- **Today.** The greeting names the next day ("Hey Alice! Ready for Push?"), followed by one big Start button, the week as day pills that wrap onto more rows, the day's movements with in-place demos, and the progress glance. The chosen day is kept in the address.
- **Finishing a workout.** A celebration ("Workout done! Nice work.") with a "New record!" ribbon when one was set. Focus moves to the heading.
- **Dark mode.** Every scene has a dusk recolour, and the scene is masked into the indigo night canvas instead of dimming daylight art. The owner asked for this.

## 3. Navigation contract

Every drill-down shows a labelled back control that returns to the exact origin. Links carry a validated `from`, `resolveBackTarget` accepts only allowlisted origins, and `BackLink` steps back in history when the previous entry is the target, so scroll comes back. Demos open in a native `<dialog>` that mounts the video only while open.

### Before (from the Phase 0 audit)

Back controls were forward links with fixed labels. Today's day picker reset on every round trip, guides always said "Library", Library search was lost, history detail always went to History, records lost their place, and the runner's demo hid in a collapsed disclosure. See [the audit's navigation map](../../plans/PLAYFUL-COMPANION-OVERHAUL.md#navigation-map).

### After

| Drill-down | Back label | Returns to | Covered by |
|---|---|---|---|
| Today → day | Back to Today | Today on the same day | `tests/authenticated-e2e/back-navigation.spec.ts` |
| Today → guide | Back to Today | Same day, same movement anchor | same |
| Day → guide | Back to Day 2 · Pull | Day page, focused on that movement | same |
| Any movement → demo | Close | Same spot, focus back on the trigger, video unmounted | same, `playful-onboarding.spec.ts`, `test-drive.spec.ts` |
| Library → guide | Back to Library | Same search, same row | `back-navigation.spec.ts` (member), `public-release.spec.ts` (public) |
| Deep link without origin | Parent fallback | Library, Today and the like | `back-navigation.spec.ts` |
| Finish workout → summary | Back to Today | Today | `back-navigation.spec.ts` |
| Records → source workout | Back to your records | Records at that record | same |
| Progress → workout | Back to Progress | Progress | same |
| Public day → guide | Back to the Push day | Day page at that movement | `tests/e2e/back-navigation.spec.ts` |
| Day opened from Today | (tab bar) | Today stays highlighted | `back-navigation.spec.ts` |

*Change from the plan:* the routine editor no longer writes `?day=` into its own address bar. Doing so made Next.js treat the post-save refresh as a different page and remount the editor, which closed open menus. The selected day still travels in the editor's links ("All routines" and every `from`).

Measured in the browser on all 42 captured screens in both themes: 3,054 samples across default, hover, real Tab-key focus, selected and disabled states. Thresholds are WCAG AA: 4.5:1 for text (3:1 for large text), and 3:1 for focus rings and selected edges.

**Before:**

- Two text pairs failed: white on a pale highlight in dark mode, 1.34:1.
- Five focus rings or control edges were below 3:1.
- The video frame had no focus ring.

**After:**

- **Text failures:** none in any state.
- **Selected states:** they all use one token set (`--selected-bg/fg/edge`), checked by `tests/unit/design-token-contrast.test.ts` in both themes.
- **Video frame ring:** browsers stop matching `:focus` once focus is inside an iframe, so `FrameFocusRing` marks the frame's wrapper. The ring measures 4.90:1 in light and 9.55:1 in dark.
- **One flag left:** the sampler still flags the focused video frame on its text check. That isn't a text pair: the frame has no text of its own.
- **Bug the browser tests caught:** teal text on the sun-yellow "Sign in" buttons inside page closers, at 4.12:1 in light and 1.01:1 in dark. It's fixed.

## 9. Fixed because the browser suites caught them

- Today's chosen day is read from the address. Next.js could reuse an earlier render, and the old state ignored the address.
- The tab bar read the address before Next.js updated it. It now uses the router's search params.
- Focus moves to the new heading after finishing a workout or leaving the tour. Before, it stayed on the document.
- The routine editor's "More" menus close properly, and the editor no longer rewrites its address. Rewriting it made Next.js remount the editor after every save.
- Primary buttons inside page closers had teal text on sun yellow: 4.12:1 in light, 1.01:1 in dark.
- A first service-worker install showed "A new version is ready" over the test drive's first button on WebKit.
- On phones, the landing "Take a test drive" button and keyboard-focused controls could sit behind the fixed tab bar. Scroll padding now keeps them clear.
- Scene art loaded lazily, and WebKit cancelled it mid-scroll. It also showed on the read-only workout screen.
- Cancelled prefetches from Settings and from in-page links on Progress, History and Records became page errors on WebKit.
- The video frame had no focus ring.
- Today had lost its link to History; it's back.

## 10. Noticed, not changed

- **Refresh responses abort in Next.js.** After any save, Next.js cancels the body of the router-refresh response (`net::ERR_ABORTED`), and `main` does the same (checked in a temporary worktree of `main` with an identical probe). `library-core-conditioning-expansion.spec.ts` waits for that response to finish, an owner-approved wait from PR #8. So it can stall until the test timeout, on either branch. It timed out in two earlier full runs and passed in the final gate run. No retry or timeout was added.
- **`pnpm db:verify` drift.** It expects the seed's 54 curated videos, but production holds 268. This predates this work, and the seed was not changed.
- **Unused fonts.** The root layouts still import Barlow Condensed, which Studio Pals no longer uses. Removing the imports would save some bytes and should be its own small change.
- **Pre-hydration input.** The owner excluded this issue earlier, and it remains excluded.
- **Full-page screenshot artefacts.** Stitched full-page screenshots painted fixed bars and the off-screen skip link mid-page. The capture tooling now grows the viewport instead. Real focus never landed on the skip link: logged focus before each capture was the expected heading or the page body.
