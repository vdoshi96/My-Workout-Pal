Companion comparison and redesign report plan

Outcome and boundary

Compare My Workout Pal and Trainpal through public browser journeys, isolated synthetic member journeys, source inspection, and a public exercise-video inventory. Deliver a standalone illustrated HTML report with canonical Markdown, a full UI redesign recommendation, original asset concepts, and an interactive simulated flow. This is a report iteration; application behavior, accounts, production data, video approvals, and publication policy remain unchanged.

Evidence and acceptance

Record exact inspected source revisions and distinguish source, synthetic fixture, and live evidence. Walk entry, example, guide, setup, home, routine editing, workout logging, reload/resume, interruption, completion, History, and Progress. Weight repeated training flow most strongly. Mark untested authentication, offline, accessibility, device, and exhaustive QA boundaries explicitly. Include reproducible findings, confidence, source references, practical deletion-first recommendations, concrete video mappings, and limitations.

The redesign must cover navigation, first use, empty and populated states, editing, active workout, rest, recovery, completion, history, progress, and account settings. Define persistence and authorization boundaries, accessible responsive behavior, assets/backgrounds/characters, and measurable future acceptance criteria. The prototype must clearly identify simulated data and must not contact application APIs or imply real saves.

Deliverables and verification

  • docs/reviews/COMPANION-COMPARISON.md and generated .html, with embedded images for standalone viewing.
  • Original concept PNG files and selected browser evidence in the report asset folder; machine-readable public checks retained without private reference material.
  • Source/HTML parity through the canonical documentation generator, browser rendering at phone and desktop widths, interactive-prototype checks, and link/image inspection.
  • Update the project status and wiki to link the report and distinguish historical release counts from observed public coverage.

No application tests are added for this documentation-only iteration. Full application QA remains incomplete for this comparative review. Git closeout follows the repository instructions. Temporary synthetic fixtures are discarded after evidence is saved; the pre-existing implementation QA report remains a separate verification record.
